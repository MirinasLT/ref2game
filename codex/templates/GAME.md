# This game: how it is built and where things go

Made with the ref2game-boosted skill. Read `study/BRIEF.md` (what the game is) and `study/PERF.md` (its budgets) before changing anything.
This file is the map for anyone (a person or an AI) who works on the game later.

## Run and check

| What | Command |
|---|---|
| Live preview (hot reload, keeps the play state) | `bash <skill>/scripts/serve.sh` (prints the URL, from port 8930 up) |
| Demo route + level self-check (seconds) | `node live/tune.cjs` |
| Frame QA: HUD boxes, anchors, touch zones | `node <skill>/scripts/qa.mjs` |
| Play-test: errors, fps, perf, menu, result card, context loss | `node <skill>/scripts/livecheck.mjs --flow` (phones: `--mobile --flow --cpu 4`) |
| Static build | `python3 <skill>/scripts/pack.py --name <name> --zip` |

Run `tune.cjs` after any sim change and `livecheck.mjs --flow` before calling something done.

## Files

| File | Owns | Edit? |
|---|---|---|
| `live/sim.js` | Everything that **happens**: rules, movement, collision, level data, entities, camera, events | Yes: the game |
| `live/scene.js` | Everything that is **drawn**: layers, placement, poses, FX from events, HUD | Yes: the look |
| `live/audio.js` | Event → sound map, voices, music | Yes |
| `live/assets.js`, `atlas.js` | Generated by `prep.py` / `atlas.py` | Never by hand |
| `index.html`, `gl.js`, `lib.js`, `input.js`, `settings.js`, `snd.js`, `collide.js` | The engine | No (`setup.sh --refresh-engine` updates them) |

## Where a new thing goes

- **New enemy, prop, pickup:** its state and behaviour in `sim.js` (an entry in a pooled array, updated in `step`, emits events),
  its look in `scene.js` (a draw function, added to the depth queue or its layer), its sounds in `audio.js`, its art as
  `art/gen/<name>.png` → `prep.py` (never a hand-made placeholder in the final game).
- **New verb (dash, attack, interact):** read the input edge in `sim.js` (`inp.act && !S.prevAct`), add it to `SIM.CONTROLS`
  (touch button) and the hint; give it anticipation, a sound, an FX and a shake from its event.
- **New level:** level data in `sim.js` (`SIM.LEVELS[i]`); keep `selfCheck()` passing (spawns in open space, pickups reachable);
  save the unlocked level in `SIM.SAVE`. Big levels: list the first frame's textures in `SCENE.BOOT`, `G.prefetch` the next level's.
- **New shader:** `L.init(W, H, { name: fragmentSource })` in `scene.js`; honour `Q` (quality tier) for anything costly.

## Rules that keep it fast and correct

1. The sim is deterministic: no `Math.random`, no `Date`, no frame time in `step`; same input → same state (the attract demo
   and `tune.cjs` depend on it). Use the integer hash `h1`.
2. Sim state is plain JSON (it survives hot reloads). Pool entities in arrays; never create objects per step in hot loops.
3. The scene never changes state; it reads `SCENE.state` / `SIM.at(t)` and draws.
4. No per-frame garbage in hot paths: hoist constant `u: {...}` records out of `render`, read `L.sprite`'s returned size
   at once, pass `G.xf` straight to `G.draw`. Many quads of one texture → `G.batch` (one draw call).
5. Every gameplay cue works at the low quality tier and on a phone (touch controls, readable HUD outside the thumb zones).
6. Size from data, not from the GPU: `L.hsz(name, h)` / `G.dim(name)` read the manifest.
7. Never rebuild input, the loop, the menu or sound plumbing in game code: configure the engine (`SIM.CONTROLS`, `SIM.LERP`,
   `SIM.PLATFORM`, events, `audio.js`).
